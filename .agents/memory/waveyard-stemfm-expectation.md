---
name: Waveyard product expectation
description: The user's core product expectation for Waveyard playback and Studio handoff.
---

Waveyard should function as a Stem.fm replacement with extra features. Live stem swapping and isolation are core capabilities, and the active stem controls should expose both directly instead of hiding source swaps in a lower-level picker. Independent stems may be swapped at the same time: apply session responses per session-track/stem channel, because out-of-order full-session snapshots can otherwise erase a different channel's newer choice or revert playback state. Speed control should offer an explicit pitch-follow versus pitch-lock choice that behaves consistently on both original and swapped layers; never expose a toggle that silently affects only one playback path. Session DJ controls should be interactive and beat-aligned, and Studio should be understandable and usable after a listening session. Mobile screenshots supplied by the user are usability references for clear, interactive controls—not pixel-perfect specifications. The user also wants TunePat/Apple Music considered as a future library source if it can be made fluid, or at minimum as a tool to back up and store their Apple Music library.

**Why:** the user explicitly described these as expected product behavior, not optional enhancements or preset content, asked for quick and visible Stem.fm-like swapping, pitch choice, DJ-style interaction, provided mobile usability references, and named Apple Music backup/library use as a future focus. Browser verification showed that separately saved stem choices can receive full session responses in reverse order, so treating those snapshots as interchangeable loses real user state.

**How to apply:** Put clearly labelled isolate and donor-swap actions together on the active stems, and verify them on desktop and mobile. Keep independent channel saves usable, merge each response only into its own channel while preserving the latest transport state, and test with reversed save and donor responses plus real audio graphs. Implement pitch-lock across original and swapped layers before presenting it as a complete mode. Use analyzed beat-grid data for loops and keep cue/loop controls reachable in the player. Prioritize reliable replacement and a clear session-to-Studio workflow. Keep the Apple Music source/backup workflow in scope. Verify real end-to-end behavior rather than relying on labels, explanations, or a build alone.
